# 프롬프트 설계서

## 1. 목표
macOS에서만 사용 가능한 MenuBar를 Windows 버전으로 만들어, Windows 사용자도 사용할 수 있는 MenuBar를 제작하고자 한다.

## 2. 맥락
Windows 사용자가 편하게 컴퓨터 상태를 확인하고 Wi-Fi, Bluetooth 등의 관리 및 상세 설정을 제어할 수 있도록 한다. 비개발자를 대상으로 하며, 일반 사용자도 해당 기능을 간단하게 사용할 수 있어야 한다.

## 기술 스택
- 외부 NuGet 패키지 없는 C# 및 .NET 10 WinForms 앱으로 개발한다.
- Windows 10/11과 설치된 .NET 10 SDK를 사용하며 시스템 정보는 Win32 API를 P/Invoke로 호출한다.
- HTML, CSS, JavaScript, React, Bootstrap, 웹 서버는 사용하지 않는다.
- 각 상태 센서는 독립적으로 실패를 처리하며, 한 센서 오류가 메뉴바 전체를 중단시키지 않게 한다.

## 3. 제약
- 기존 Windows OS 기능을 제한하는 기능을 넣으면 안 된다.
- CPU/GPU/RAM을 사용할 때 발열/성능 저하/배터리에 부담을 주어서 노트북 성능 저하를 야기하면 안 된다.
- 기본 디자인은 일반 MacBook MenuBar를 기준으로 만들면 된다.
- 기존 노트북에 깔린 앱과 실행중인 모든 프로그램에 기능을 제한하는 기능은 추가되면 안 된다.

## 4. 출력 형식
- 기본 macOS MenuBar 디자인을 기준으로 깔끔하게 디자인해줘
- 마지막에 완료 기준을 하나씩 어떻게 확인할지 적어줘

## 5. 완료 기준
- 기본 MacOS menubar같이 컴퓨터 상태를 체크할 수 있다.
- 기존 노트북에서 실행하던 앱에 대한 기능 제약을 하지 않는다.
- 기존 노트북 OS 기능을 제한하지 않는다.
- 노트북을 재시작해도 알아서 OS의 원래 기능처럼 다시 켜지고, 설정이 저장된다.
- 쉽게 깔아서 사용할 수 있는 구조를 가진다.
- 유휴 상태에서 CPU 사용률은 평균 1% 이하, 메모리 사용량은 20MB 이하를 유지한다.
- 시스템 상태 갱신 주기는 2초 이상으로 설정하여 CPU/GPU/RAM과 배터리에 과도한 부하를 주지 않는다.

## 6. 모호한 요청 vs 구체적인 요청 비교
| 비교 항목 | 모호한 요청 | 구체적인 요청 |
| --- | --- | --- |
| 상태 표시 항목 | 컴퓨터 상태를 보여준다 | CPU, GPU, RAM, 배터리, 네트워크, 음량과 시간을 표시한다 |
| 설정 제어 범위 | 컴퓨터 설정을 관리한다 | Wi-Fi, Bluetooth 등은 안전한 제어 또는 Windows 상세 설정 연결만 제공한다 |
| 성능 기준 | 성능 저하가 없어야 한다 | 유휴 CPU 평균 1% 이하, 메모리 20MB 이하, 상태 갱신 주기 2초 이상을 유지한다 |
| 자동 실행 방식 | 재시작해도 다시 켜진다 | 사용자 동의를 받아 로그인 시 자동 실행하고 저장된 설정을 복원한다 |
| 기존 기능 보호 | 다른 기능을 방해하지 않는다 | Windows OS 기능과 설치·실행 중인 앱을 차단하거나 제한하지 않는다 |

## 7. 무엇이 달라졌고 왜 달라졌나
초기 요청보다 대상 사용자, 제공 기능, 성능·호환성 제약과 완료 기준이 구체적으로 정의되어 구현 범위가 명확해졌다.
특히 기존 OS와 앱을 제한하지 않는다는 원칙과 재시작 후 자동 실행·설정 저장 조건을 추가해, 안전성과 사용 편의성을 검증할 수 있게 되었다.
