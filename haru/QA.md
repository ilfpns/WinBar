# QA 로그

Haru를 점검한 기록. 새 항목은 맨 위에 적는다. 문제는 번호를 붙이고, 처리 결과(고침 / 보류 / 사양대로)를 함께 적는다.
점검은 사용자의 브라우저가 아니라 별도의 헤드리스 브라우저(gstack browse, `http://localhost:5288`)에서 한다.

## 2026-10-20 (v1.16)

**애니메이션 끊김** (사용자 제보) — 프레임 간격·긴 작업(long task) 측정, 헤드리스(소프트웨어 렌더링)라 절대값보다 전후 비교로 판단
| 동작 | 전 (20ms 넘은 프레임 / 시작 비용) | 후 |
| --- | --- | --- |
| 서랍 열기·닫기 (Today) | 2~14개 / 25~86ms | 0개 / 0~1ms |
| 서랍 열기·닫기 (Journal) | 5~8개 | 0개 |
| 나의 하루들 펼치기 | 2개 / 71ms | 0개 / 1ms |
| News 서랍 열기·닫기 | 15~23개 | 0개 |
| News 가만히 (지구본) | 24/63 | 0/73 |
원인과 처리
1. 서랍만 열어도 모든 구독자(다이얼·목록·개요·통계)가 다시 그림 — **고침**: 서랍만 바뀌면 서랍 관련 구독자에게만 알림.
2. 나의 하루들 펼칠 때 차트를 그때 만들어 첫 프레임이 끊김 — **고침**: 접혀 있을 때 한가한 시간에 미리 그리고, 펼칠 때·페이지에 들어올 때는 막대만 다시 자라게.
3. 지구본이 매 프레임 점 약 4,000개를 그림 — **고침**: 뒤편 점은 절반을 사각형으로, 서랍이 움직이는 동안은 마지막 프레임 유지, 돌아올 때 같은 그림이면 다시 그리지 않음.
4. 출석 막대 폭 애니메이션의 레이아웃 범위 — `contain: layout paint`.

**채팅·보드·인용/콜아웃** (가짜 Firestore)
- 서식 메시지(굵게·목록) 표시, Enter 보내기, 목록 안 Enter는 다음 항목, 이모지 삽입, Ctrl+V 사진(900×600 → 5KB 대 JPEG) 보내기·표시.
- 보드: 획 저장(42점), 되돌리기, 열기·닫기.
- `| ` 인용, 표 줄은 표 그대로, `> [!note]` 콜아웃 아이콘·Enter로 잇기, `/call` → Callout, 렌더러에서 같은 종류만 한 상자.

**찾은 문제와 처리**
1. 채팅 메시지 글자가 안 보임(`md-view` 클래스가 기본 숨김) — **고침**: 채팅 전용 클래스.
2. 다른 종류 콜아웃(note·warning)이 한 상자로 합쳐짐 — **고침**: 같은 종류끼리만 묶음.

**아직 못 본 것**
- 실제 Firestore: 채팅 사진·보드 규칙 추가, 콘솔에 다시 게시 필요.
