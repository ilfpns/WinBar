## 2026-10-20 (v1.26) — 성능과 반응형

**측정 방법**: 배포와 같은 빌드(vite preview), 헤드리스 Chrome 60fps. 클릭 → 화면 반영 시간과 50ms 넘는 긴 작업, 가만히 있을 때 CPU(ms/s), CPU 프로파일.

**찾은 원인과 처리**
1. 페이지 이동 때 다이얼 위치 계산이 CSS 변수를 읽으며 문서 전체 스타일을 즉시 다시 계산(Calendar 34ms, News 96ms) → 다음 프레임으로 미루고 Today에서만 계산, 크기는 ResizeObserver로 받아 둠.
2. 다이얼 점 애니메이션이 다른 페이지에서도 매 프레임 깨어나 offsetWidth로 레이아웃 강제 → 보이지 않으면 루프 정지, 크기 캐시, 아무 조작이 없으면 30fps. 색 계산(getComputedStyle)도 테마별로 캐시.
3. 지구본이 켜질 때 offsetWidth·색을 다시 읽어 71ms 멈춤 → ResizeObserver 값 사용, 아무 조작이 없으면 30fps.
4. 할 일 편집기가 열리자마자 focus()로 레이아웃 강제(76ms) → 다음 프레임에 preventScroll로.
5. v1.24에서 넣은 body 클래스 감시가 애니메이션 중 클래스가 바뀔 때마다 다이얼 위치를 다시 계산 → "다른 사람 보기" 변화에만 반응.
6. 서랍이 움직이는 동안 28px 배경 흐림을 매 프레임 다시 계산 → 움직이는 동안만 끔(페이지 전환과 같은 방식).
7. 시험해 보고 되돌림: 숨은 페이지에 content-visibility:hidden → 클래스 변경은 빨라졌지만 페이지에 처음 들어갈 때 100~140ms 멈춤이 생겨 되돌림.

**전후 비교** (클릭 → 반영, ms)
